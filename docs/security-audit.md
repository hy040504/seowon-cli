# seowon cli 공개 전 보안 감사

2026-10-10에 TypeScript TUI, 서비스 계층, 복사된 API 엔진, 배포 파일, 문서·미디어 및 도달 가능한 Git 이력을 점검했습니다. 패키지 버전은 `1.0.0`입니다. 보안 감사와 이력 정리 결과를 반영한 현재 소스로 새 main 이력을 시작했습니다. 이전 개발 이력과 커밋은 새 저장소에 업로드하지 않았습니다. 새 릴리스 버전이나 CVE 번호를 부여하지 않았습니다.

실제 계정 녹화에서 이름·학번·소속·성적·수강 정보 노출을 확인했고, 현재 공개 자료에서 제거했습니다. 통신·인증 상태·오류·로그·터미널·파일 저장의 문제도 보강했습니다. **과거 이력도 모든 브랜치·로컬 참조에서 정리했고 현재 파일·이력 검사 후보는 모두 0건입니다. GitHub 캐시와 외부 사본의 완전 삭제는 별도 절차가 필요합니다.**

## 프로젝트와 감사 범위

`lib/front/tui`가 메뉴를 표시하고 `Campus`가 한 사용자의 메모리 세션과 캐시를 관리합니다. `lib/back/services`가 학교 응답을 가공하며 `lib/back/engine`의 클라이언트가 e-campus·수강·ERP에 직접 요청합니다. 이 엔진은 `seowon-client-api`를 복사한 코드여서 원본 SDK의 수정이 자동으로 반영되지 않습니다.

현재 소스에는 자체 HTTP 서버, `/api/admin` 라우트, DB 스키마·ORM·SQL 실행 계층이 없습니다. 과거 `db/testdata`의 학생 응답 JSON은 학교 백엔드의 DB 스키마나 관리자 기본 계정의 증거가 아닙니다. 이 감사로 다른 웹 프로젝트나 학교 백엔드의 DB 추출·관리자 권한 획득 가능성을 확인한 것으로 해석할 수 없습니다.

검증은 가상 계정·응답·파일과 로컬 미리보기로 수행했습니다. 실제 학교 로그인·조회·과제 제출·삭제·시청 기록 적재는 실행하지 않았습니다. HTTP 테스트에는 native HTTP·HTTPS·socket·TLS 연결 차단을 적용했습니다.

## 공개 정보와 Git 이력

검사 시작 시 HEAD 이력은 43개 커밋, 모든 참조의 도달 가능한 이력은 52개 커밋입니다. 이력 스캐너 후보 50건은 서로 다른 취약점 50개를 뜻하지 않습니다.

| 후보 종류 | 수 | 의미 |
| --- | ---: | --- |
| student-identifier | 19 | 여러 버전의 README·학생 JSON에 남은 학번 형태 |
| student-name | 17 | 학생 이름 필드·예시의 실제 이름 후보 |
| historical-media-review | 14 | 11개 GIF, 2개 PNG와 과거 로딩 아이콘. 검토한 가상 시간표·아이콘도 수에 포함 |

공개 녹화 11개는 원래 실제 조회 8개와 가상 시연 3개로 표시되어 있었습니다. 개인정보를 확인한 자료와 전체 프레임 검토가 끝나지 않은 자료를 함께 제거했으므로, 11개 모두에서 같은 개인정보를 확정한 것으로 계산하지 않습니다.

현재 제거한 12개 미디어의 원본은 무시되는 `.local/security-media/originals`에 보관합니다. 이 폴더를 포함한 작업 디렉터리 전체를 ZIP으로 공개하면 안 됩니다. 남은 `timetable-example.png`는 가상 과목·교수·강의실 표기와 이미지 내용을 확인했고 별도 PNG 텍스트·EXIF 메타데이터가 없습니다. 공개 자료 색인은 실제 촬영 원본 경로 대신 검토 정보와 해시만 보관합니다.

현재 코드·문서 검사에서는 비밀번호·DB 접속정보·관리자 기본 계정·서비스 토큰 후보가 남지 않았습니다. Git 메타데이터의 이름·이메일은 각각 1종이며 이메일은 GitHub noreply 형식입니다. 이름·임의 형식 식별자는 사람이 검토해야 하고, 스캐너가 모든 개인정보를 발견한다고 보장하지 않습니다.

`.env`, `data`, `downloads`, `.local`의 Windows ACL에서 Everyone·Authenticated Users·일반 Users에 대한 허용 규칙은 0개였습니다. 이 결과는 현재 기기의 확인된 폴더에만 해당하며 Administrators·SYSTEM·소유자의 접근을 차단한다는 뜻이 아닙니다.

정리 전의 50개 후보와 별도로 모든 객체를 직접 검사해 README·C·Python 11개 경로의 실제 이름·학번 및 소속명을 치환했습니다. 독립 검사에서 정리 직후 53개 커밋·505개 객체의 원문·Unicode 해독 결과는 0건이며, 제거한 15개 경로도 모든 커밋에서 사라졌습니다. 자세한 절차와 비공개 백업 관리는 [이력 정리 문서](history-cleanup.md)에 있습니다.

파일 테스트는 취소·스트림 실패 시 기존 파일 보존과 임시 파일 정리, 동시 저장, 링크·업로드 크기 제한을 확인했습니다. POSIX 모드 검증은 Windows에서 실행되지 않으며 CI의 Ubuntu 환경에서 적용됩니다. timeout·logout은 로컬 작업과 늦은 로그인 반영을 중단하지만 이미 전송한 학교 요청의 외부 처리를 되돌리지 않습니다.

세션 테스트는 서비스의 OTP 거부, 이전 계정 초기화, 로그아웃·시간 초과 뒤 늦은 로그인 차단, 늦은 SSO 응답이 새 학생 프로필을 덮어쓰지 않는 것을 확인했습니다. TUI 테스트는 실제 원본 선택값·파일 경로를 보존하면서 표시에서 제어 문자를 제거하고, 명시적 .env 계정 전환 때 기존 세션을 재사용하지 않는 것을 확인했습니다.

Chrome DevTools로 가상 시간표의 서비스·엔진 HTML을 데스크톱 1440×1080 및 모바일 390×844에서 캡처해 확인했습니다. 악성 img 문자열은 텍스트로 표시되고 script·img·iframe 주입은 0개였습니다. 제목·과목·요일의 간격과 가로 스크롤을 확인했고, 모바일에서는 서비스 710px·엔진 742px까지 스크롤해 오른쪽 요일을 볼 수 있습니다.

TUI는 브라우저 앱이 아니므로 가상 입력 스트림으로 실제 키 처리의 비밀번호 마스킹·Enter 완료·방향키 선택·Esc 취소를 실행했습니다. 그 출력을 로컬 HTML로 표시해 데스크톱·모바일 이미지의 잘림·간격을 확인했습니다. 실제 OS 터미널 렌더러 전체를 Chrome으로 검증한 것은 아닙니다. 로컬 HTTP 미리보기의 콘솔 오류·경고는 0개이고 네트워크는 각 로컬 문서 200 응답만 발생했습니다. 최초 file URL 미리보기에서 Chrome의 고유 origin 경고가 있어 localhost 미리보기로 다시 확인했습니다.

| 재현 조건 | 개인정보 포함 녹화 열람, 민감한 객체·로그 출력, 공격자 제어 URL·제어 문자 또는 마스킹 불가 입력 등 항목별 조건 |
| 영향 | 학생 정보·인증정보 노출, 잘못된 로컬 인증 상태, 파일 손상·중복 변경 요청 등. 학교 관리자 권한 획득은 확인하지 않음 |
| 검증 자료 | 실제 값을 제외한 오프라인 회귀 테스트와 수정 소스 |
| CVE 상태 | 미신청·미할당. CVSS 점수와 영향 버전 전체는 CNA 검토 전에 확정하지 않음 |

단순 실수로 공개한 계정 자료와 운영 환경의 권한 설정까지 모두 독립적인 제품 CVE로 인정된다는 뜻은 아닙니다. 새 공식 번호 대신 실제 수정과 근거를 기록했습니다.

## 남은 조치와 제약

현재 소스 보강과 과거 이력 정리를 완료했습니다. [이력 정리 결과와 이전 안내](history-cleanup.md)에 따라 기존 복제본을 새로 복제해야 합니다. GitHub 캐시·외부 사본의 개인정보가 모두 삭제된 것으로 간주하지 않습니다. 실제 비밀번호·세션 노출이 확인되면 학교 계정에서 변경·폐기하고, 모든 프레임이 검토되지 않은 실제 실행 녹화는 다시 공개하지 않습니다.

학교 레거시 로그인은 DES 계열 패킷과 패킷 안에 포함되는 키를 요구합니다. 난수를 보강해도 이 형식 자체가 강한 별도 기밀성을 제공하지는 않습니다. 서버 호환성을 유지했으며 전송 기밀성은 HTTPS에 의존합니다. 프로토콜 상수나 학교 공개 경로를 DB 비밀번호·관리자 시크릿으로 분류하지 않습니다.

학교 인증·권한 검사, 서버 DB, 계정 잠금·OTP 정책은 이 클라이언트로 수정할 수 없습니다. 명시적으로 민감한 엔진 accessor·응답과 프로그램 메모리를 다루는 개발자 코드, 사용자가 열어 보는 개인 학사 화면, 파일을 보관하는 기기·백업의 접근 권한도 별도로 관리해야 합니다.

엔진의 `registerCourseWithRetry`처럼 호출자가 명시적으로 선택하는 재시도 도구는 별도 기능이며 CLI에서는 사용하지 않습니다. 변경 요청의 전송 계층 재시도 차단이 이런 도구의 모든 동작을 제거했다는 뜻은 아닙니다.
