# engine

학교 e-campus, 통합정보(ERP)와 **직접 통신**하는 외부 연동 계층입니다.

업무 로직·목록 가공·제출 오케스트레이션은 `lib/back/services` 가 맡습니다.  
이 폴더는 로그인·쿠키·학교 요청과 응답 프로토콜을 다룹니다. 웹 서버는 이 저장소에 없습니다.

원본은 [seowon-client-api](https://github.com/hy040504/seowon-client-api) 이고, SAZ 분석·개설 DB는 가져오지 않았습니다.

| 폴더 | CLI에서 쓰는 일 |
| --- | --- |
| `ecampus/` | 로그인, 과목·과제·공지·자료·이러닝 URL·현재 학기 성적 조회 |
| `erp/` | 통합정보시스템 로그인, 지난 성적(학기 선택) 조회 |
| `hope-basket/` | 수강희망바구니 로그인·조회·담기·취소·시간표 |
| `course-registration/` | 확정 수강 목록·시간표 SVG |

공개 진입점은 `index.ts` 입니다.

`lib/back/engine/ecampus`, `lib/back/engine/erp`, `lib/back/engine/course-registration` 은 이 계층 내부 경로입니다.  
화면용 가공은 `lib/back/services/ecampus`, `lib/back/services/erp`, `lib/back/services/timetable` 에 있습니다.

이 코드는 별도로 복사해 관리하는 모듈입니다. 원본 SDK를 수정해도 이 저장소에 자동으로 반영되지 않으므로, 두 저장소의 보안 변경을 함께 검토해야 합니다.

2026-10-10 보안 감사에서 다음 경계를 보강했습니다.

- 서비스별 정확한 HTTPS 출처와 동일 출처 리다이렉트만 허용합니다. 로컬 소켓과 환경변수 프록시를 통한 우회도 차단합니다.
- OTP가 필요한 응답과 로그인 화면에서 받은 쿠키를 인증 완료로 처리하지 않습니다. 계정 변경 시 이전 쿠키·학생 문맥을 비웁니다.
- 클라이언트 JSON·콘솔 검사와 HTTP 오류에서 계정, 쿠키, 요청 본문, 서버 원문을 제외합니다. 과제 원문 디버그 로그도 제거했습니다.
- 미디어는 별도 HTTP 인스턴스로 받아 인증 쿠키·헤더를 공유하지 않습니다. 허용된 콘텐츠·MP4 출처를 검사하고, 다운로드 실패 시 기존 파일을 보존합니다.
- 로그인 키는 `node:crypto`의 안전한 난수로 생성합니다. 학교가 요구하는 기존 DES 패킷 형식은 유지되며, 전송 기밀성은 HTTPS에 의존합니다.
- HTTP 전송 계층에서는 조회 요청만 자동 재시도합니다. 저장·취소 요청이 암묵적으로 중복 전송되지 않도록 했습니다. `registerCourseWithRetry` 같은 명시적 재시도 도구는 별도 기능이며 CLI에서는 사용하지 않습니다. 시간표의 교시·요일·파일명도 제한합니다.

메모리로 모으는 HTTP 응답은 최대 64 MiB, 요청 본문은 최대 128 MiB입니다. 첨부 다운로드와 사용자 업로드에는 각 기능의 더 작은 제한이 적용됩니다. MP4 스트림은 메모리에 모으지 않습니다.

주요 분류는 CWE-20/22/400, CWE-200/209/532, CWE-287/522/523, CWE-338, CWE-841입니다. 자세한 근거와 한계는 [보안 감사 보고서](../../../docs/security-audit.md)를, 비공개 제보와 공개 전 확인사항은 [SECURITY.md](../../../SECURITY.md)를 참고하세요. 새 CVE 번호가 발급된 것으로 표기하지 않습니다.

`getCredentials()`, 로그인 응답의 `data`·`raw`, 공개 `cookieJar`·`http`를 직접 읽는 호출은 민감한 정보를 취급합니다. 주입한 함수 어댑터는 호출자가 신뢰하는 코드이며 요청 경계의 실행을 우회할 수 있는 임의 코드로 취급해야 합니다. 이 연동 계층은 학교 백엔드의 권한 검사나 DB 보안을 대신하지 않습니다.
